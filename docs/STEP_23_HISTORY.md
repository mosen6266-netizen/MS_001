# 第23步：历史、审计和安全诊断包

## 已开发模块
- SQLite v10 的 history_events 独立于原始任务、发送事务和回执数据库。仅存固定事件分类、严重程度、时间、去重来源键及本地运行GUID。
- HistoryRepository 从持久化的模拟调度状态、投递事件提取受控分类；重复提取不会重复插入。游标分页每页10/20/50条，可按严重程度、内部任务GUID筛选，不使用OFFSET深翻页。
- Windows原生顶部“任务历史”窗口包含严重程度筛选、10条一页的分页、事件描述、脱敏诊断ZIP导出、保留期选择和手动清理。
- SupportBundleBuilder生成固定的3个文件：manifest.json、summary.json、timeline.jsonl。最多200条事件，总大小不超过256KiB。只含事件类型、等级、时间、统计和随机工单编号；没有账号、群、运行GUID、投递GUID、消息正文、授权资料、磁盘路径和原始数据库。
- 派生历史保留7/30/90/180/365天，或输入“清理历史”后全部清理；清理只影响history_events，并保留HistoryPurged记录。不会改动原始回执、账户、剧本、隔离数据或紧急停止闩锁。
- SafeDiagnosticLogRetention仅处理诊断目录下两个固定日志文件，不递归处理其他文件，也不跟随文件重解析点。

## 验收与限制
- tests/History 使用真实100,000条SQLite事件、100页游标分页、严格枚举和上下文过滤、脱敏ZIP检查、保留与清理及原始数据完整性检查。
- 本阶段是离线模拟记录与审计元数据。没有接入真实TDLib生产发送，不会伪造正式网络投递结果。
- Windows10/11真实机器视觉体验、历史长稳性能和实际合法群发送，在后续整合及最终实机阶段验证。
