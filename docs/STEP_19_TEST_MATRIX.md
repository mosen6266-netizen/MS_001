# Step19 回执与去重开发测试矩阵

- v1→v8 与 v7→v8 数据库迁移、原有账号/剧本/权限数据保留、重复初始化无副作用。
- 创建前：拒绝早于发送前等待 / 正在输入结束的事务，拒绝跨账号、跨群错配；创建成功后独立 `attempt_id` 和 `correlation_id` 被原子保存。
- 唯一约束：相同运行/消息步骤重放同一许可幂等，换许可拒绝生成第二笔；不同消息不得占用同一个账户×群平台消息ID。
- 乱序：Pending先于提交拒绝，官方Confirm先于Pending在可信、关联完整时安全处理；后续迟到Pending不能覆盖已确认。
- 失败分级：明确非送达与超时/断网/未经验证响应分开，结果不明只能 Unknown，禁止自动补发/重复提交，晚到可信官方确认可以解除Unknown。
- 回执真伪：缺官方可信来源、账号错误、群错误、消息ID不合规、矛盾回执和重复回执均不能误确认。
- 重启：Planned→Review、Submitting/Pending→Unknown，Confirmed/Failed保持；需人工复核记录可列出，但不会向Telegram发送。
- 自动重试只允许纯读列表；发文字、图片、未知操作不允许自动重试。
- Windows/Linux .NET10 运行全部真实断言，旧 SQLite v8、安全策略、脚本 ZIP、50群模拟、UI 页面静态/截图回归。
- Win10/11真实 TDLib 服务端回执、权限、断网/强退、50群长稳与72小时系统测试标记 DEFERRED。
