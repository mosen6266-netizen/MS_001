# MOSEN Telegram Scheduler — 安全故障排查

适用于MS_001开发候选。真实Win10/11、TDLib、签名更新和云端授权尚未正式验收，不涉及Signal MS002。

| 现象 | 建议操作 | 禁止操作 |
|---|---|---|
| 安装包签名未知、SHA不符 | 停止安装，核对官方发布签名和可信哈希 | 不关闭安全软件强行运行 |
| Windows启动白屏、WebView2报错 | 退出后核对运行时、OS版本、磁盘和企业策略，保存脱敏错误码 | 不删除整个用户配置目录 |
| 更新失败、无法重启 | 保留previous-program、previous-program.prior、pending和last-update-error.txt，检查恢复指南 | 不随意删除未完成备份 |
| SQLite结构异常、迁移失败 | 关闭应用、保护app.db/WAL/SHM及备份，制作完整副本后验证恢复候选 | 不直接覆盖正在使用的数据库或WAL |
| QR、验证码、2FA异常 | 在合规环境核实是否收到真正的官方TDLib状态；停止尝试 | 不循环刷码或绕过授权 |
| 不在群内、被禁言或慢速模式 | 先核对实时群/话题权限，人工纠正映射 | 不切换其他未授权账户冒充发送 |
| 发送结果不明 | 保留Review，人工核对官方聊天消息及回执 | 不盲目重发 |
| 网络恢复或系统休眠后暂停 | 重新预检群成员和消息状态 | 不自动补发停机期间积压内容 |
| 卡密验证失败或云端失联 | 检查仅Telegram专用地址、签名票据及当前许可；正式服务仍未部署 | 不复用Signal MS002卡密后台或关闭证书校验 |
| 检查更新拒绝 | 验证发行者公钥已正式配置；开发版UNCONFIGURED为预期拒绝 | 不把无签名dev包改名成V1.0 |
| 系统卡顿或闪屏 | 记录版本、操作步骤、操作系统、可复现时间，使用脱敏诊断ZIP | 不提交原始账号、会话、验证码和聊天数据 |

## 生成安全的支持信息

使用任务历史中的脱敏诊断导出（固定错误类别/摘要）。截图遮盖账号、邮箱、手机号、群邀请链接、验证码及任何钱包地址。提供准确操作步骤与Windows版本即可；不要公开原始数据库或云端Secret。

## 升级或恢复原则

先停止并保存数据；再检查数据库完整性和迁移SHA；只有完全退出且有独立副本时才人工处理恢复候选。安装程序签名错误、未知回执或TDLib权限异常属于默认拒绝而不是应当绕过的故障。参阅 [数据恢复](RECOVERY_GUIDE.md) 和 [安全审核](SECURITY_AUDIT.md)。
