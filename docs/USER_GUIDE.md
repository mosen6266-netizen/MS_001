# MOSEN Telegram Scheduler — 用户指南（V1.0 开发候选）

适用 Windows 10/11 x64 的 MS_001 独立第三方桌面工具，**不是Telegram官方客户端，也不是Signal MS002**。

**发布状态：BLOCKED。** 当前仅有可编译的未签名开发安装包、离线数据/界面/模拟状态机。原生TDLib实际账号授权与真实Telegram发送、Cloudflare生产许可证、300在线账号、50真实群、连续72小时、签名自动更新均未完成真实验收，**不应在生产账号环境中使用本开发包**。

## 1. 安装与文件位置
- 当前GitHub CI临时开发包名：MOSEN-Telegram-Scheduler-Setup-0.27.0-dev.exe；未签名，不是正式V1.0。正式名称仅在获得可信签名和人工批准后使用。
- 安装目标：%LOCALAPPDATA%\Programs\MOSEN\TelegramScheduler；桌面及开始菜单快捷方式启动同一EXE。
- 私人数据：%LOCALAPPDATA%\MOSEN\TelegramScheduler；SQLite app.db、backups、诊断、WebView2配置和后续会话数据均与程序目录分离，不与Signal共享。
- Windows离线安装器设计为包含.NET桌面运行环境和WebView2 x64，用户无需安装Python、Java或signal-cli。此项已编译验证，干净Win10/11真正安装、卸载和覆盖恢复仍待实机验证。

## 2. 账号和群权限
- “账号管理”的备注和列表当前支持本地元数据登记；300条元数据容量测试**不代表**300个Telegram账号已在线。
- 真正账号授权必须由本人使用官方QR、验证码/邮箱/双重验证并得到Telegram实际Ready状态才可视为完成。离线认证状态预览不代表已登录。
- 选择群组/话题需校验账号是真实成员并有发送权限。重复备注或缺失角色账号应人工确定，不得以其他账号冒充或绕过平台慢速模式。

## 3. 剧本和计时
- 剧本编辑支持角色、消息及三段独立计时：发送前等待→正在输入→提交→明确回执→发送后等待。
- 例：发送前等待30秒、正在输入5秒，35秒时才进入“可提交”阶段；发送后等待从确认后算起。模拟调度界面出现“待发/已完成”不代表Telegram真实收到消息。
- 剧本可跨设备导入导出，只携带内容/角色/计时/受控媒体，不包含登录凭据和真实会话。每次导入都要重新绑定本机角色及确认群权限。

## 4. 运行、异常和紧急停止
- 本地模拟支持50个独立群组任务及冻结前权限检查。账号权限失效、网络故障或回执不明时应进入人工复核，**不允许自动补发未知结果**。
- 停止操作持久化；重启也不应静默恢复异常任务。消息发送与真实TDLib投递尚未完成真实生产联调，不要将本地模拟作为群内实际发送工具。

## 5. 诊断、备份与卸载
- 历史页面可导出脱敏诊断ZIP，不要公开上传原始app.db、会话目录、API密钥、验证码或完整聊天记录。
- SQLite一致性备份位于backups；PrepareRestore只生成独立、经过数据库完整性/迁移哈希验证的候选文件，不自动覆盖现存app.db。
- 默认卸载保留用户数据，彻底删除需要独立工具和精确授权确认。真实Win10/11数据保留还需要实机验收。
