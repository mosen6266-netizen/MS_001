# 第24步｜Windows性能剖析、资源预算、降级和订阅清理

## 范围与真实性
本阶段针对 MS_001 的**离线Windows WPF壳、50群模拟状态与本地数据**建立资源门槛。没有正式TDLib发送账号，也没有实际 Windows10/11 长达8小时的真人桌面/网络测试。测试中的“8小时”是28,800秒逻辑时钟快速推进，不能冒充真实8小时运行结果。

## 资源观察和预算
- `src/Core/ResourceBudget/ProcessResourceSampler` 使用当前进程的处理器累计时间差 / 物理墙钟及逻辑处理器数，估算CPU占用百分比；采集Working Set、GC堆、线程数及 Windows可用时句柄数；不支持平台的句柄不当作零值触发误报。额外输入计时器订阅、缓存条目与诊断JSONL字节数，不涉及帐号、手机号、运行ID和任何网络信息。
- `ResourceBudgetMonitor` 对连续两次超限才提升等级、连续三次正常才恢复，避免零星突发产生弹窗洪水。同类压力30分钟才重复提醒。
- 预算（保守开发基线，不是Telegram官方要求）：
  
| 指标 | 降频警戒线 | 严重警戒线 |
|---|---:|---:|
| CPU（进程占总可用逻辑CPU） | 70% | 95% |
| 工作集内存 | 500MiB | 850MiB |
| 托管堆 | 220MiB | 440MiB |
| 线程 | 80 | 150 |
| Windows句柄（Linux不评估） | 1200 | 2400 |
| 本地监控/业务定时器登记 | 4 | 10 |
| LRU缓存项 | 768 | 1024 |
| 原始诊断文件总字节数 | 384KiB | 512KiB |

- 正常：运行中心只读轮询每5秒、通知扫描6秒；接近上限：15/30秒；严重：30/60秒。倒计时始终共用页面一个1秒刷新计时器，**不减少重要紧急停止和可靠性门禁**。
- 资源监控由 WPF 单个后台优先级的15秒 DispatcherTimer 驱动，采样只使用当前进程及最多两个诊断文件大小。ResourcePressure 通知经既有“单窗口、20秒托盘节流、同一错误合并”机制展示。资源降级不开放任何Telegram发送权限，不会因UI慢而改变原始出站提交逻辑。
- `ResourceTrend` 以每分钟最后一次汇总观察保存最多480点（8小时）；不保存用户标识。多余采样覆盖旧记录，长期运行数据内存上限固定。
- `BoundedLruCache` 提供容量1~1024的线程安全LRU接口（按Key覆盖、LRU驱逐、Clear），不允许无界缓存。它是未来非敏感显示数据的缓存原语，当前未缓存账号会话、密钥或消息正文。UI读取不因缓存错乱而成为发送依据。

## 消除监听和定时器泄漏
- 用 `SubscriptionRegistry` 管理 WebView2 三类导航/新窗口事件与消息IPC事件；不再注册无法解除的匿名导航lambda。关闭主窗体时统一取消 CoreWebView2 事件监听，然后停止资源时钟、通知时钟、托盘、对话框，最后Dispose浏览器。防止关闭后仍有订阅持续持有窗体。
- 同样登记 NotifyIcon 双击和 DispatcherTimer Tick 取消监听回调；晚于关闭到来的新监听会马上注销，Dispose幂等。
- React运行中心 `useEffect` 在切换页后取消一个秒钟计时器及 WebView2 消息监听；读取周期由桌面资源策略下发 `pollHintSeconds`（5/15/30），字段经严格的 IPC 客户端校验；除任务只读状态外无其他业务能力。
- 通知扫描保留 `_refreshingAlerts` 防重入；WPF资源采样在 DispatcherPriority.Background 执行，异常安全降级、不阻断按钮与界面。

## 基线测试与真实验收
- `tests/Performance` 在 Windows/Linux 跑CPU突发/高内存/句柄/线程/定时器/缓存/诊断文件分级、温和恢复与冷却、20000项LRU淘汰及并发、窗口闭合100条订阅释放、28,800次一秒逻辑样本、480点时序环、GC retained-memory上限、实际本机资源读数和小型诊断日志轮转。
- 同一个 CI 必须继续通过 WPF win-x64 发布、全部此前 SQLite、50群、通知、审计和UI测试。
- **DEFERRED**：真实 Windows10/11 8小时CPU/内存/句柄曲线、多个真实TDLib账号50群长跑、WebView2显存和浏览器子进程、杀软/睡眠重启/高DPI异常、72小时发行验收。第24步并不证明这些生产场景已达到预算阈值。最终完整包安装后用户集中实测。
