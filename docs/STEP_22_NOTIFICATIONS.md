# 第22步｜Windows 提醒、托盘与紧急停止

## 交付范围

- `src/Desktop/Notifications/NotificationCenter.cs` 维护本地通用事件类别，按事件类型及安全记录ID合并重复告警并记录发生次数；默认同一事件5分钟静默期，最多保留500条，线程安全；拒绝原始错误信息、手机号、路径与非法自由文本进入标识。
- `AlertHistoryStore.cs` 在当前 Windows 用户的 `%LOCALAPPDATA%/MOSEN/TelegramScheduler/alerts.json` 中原子保存**仅类别、抽象记录ID、时间、次数、确认状态**；不保存手机号、聊天文字、session、官方异常堆栈或令牌。异常JSON不会直接反馈给界面。
- `EmergencyStopController.cs` 的阻断顺序：立刻关闭共享的本地模拟出站许可；在 `emergency-stop.latch` 原子写入永久停止标记；创建已经存在的模拟调度器并对所有非终态任务执行单次SQLite事务 `StopAll`。如果磁盘不可写，仍保留本进程锁闭并返回明确 `LATCH_WRITE_FAILED`，不能虚称持久成功。重启时识别停止标记并维持模拟出站许可关闭。重复触发幂等，不会重复提交发送。
- Windows 原生 `apps/desktop/MainWindow.Notifications.cs`：仅桌面窗体存在时创建托盘图标和单个6秒周期的只读异常扫描；最新本地 SQLite 模拟任务若为 Failed / Review / 结果未知，显示中文通知、托盘提示并复用一个始终置顶的告警窗口。没有异常不弹窗。最多同时出现一个告警窗口。
- 主窗体顶部始终能看到 **全局紧急停止** 与 **异常历史**。托盘菜单含“打开主窗口”“查看异常历史”“全局紧急停止”“退出程序”。双击托盘可恢复窗口；关闭窗体会销毁托盘和所有定时器，**不会仅缩到后台继续运行**。
- 全局停止确认窗口明确展示后果；**确认按钮在左（绿色），取消在右（红色）**。取消不产生停止操作。窗口会提示停止标记或模拟落盘失败需人工核对。
- WPF 实际 UI 与持久化模型严格区分：当前还未连接真实TDLib发送服务，因此任何通知只来源于本地模拟数据库，紧急停止只控制当前离线策略与模拟任务，**不能宣称已停止不存在的真实Telegram发送**。
- 后续第23步对任务历史、审计安全导出进行可检索优化。本步异常历史是受限的用户本地状态，不代替正式任务审计。

## 安全边界与局限
- 停止标记不可通过网页IPC清除；真实发送仍未开启，也不能在浏览器中发送自定义异常或触发发送。未来正式 TDLib 发送适配器必须在每次真实发送前读取同一安全闩锁并共享全局停止门禁；Step22 本身还未集成正式网络传输。
- 实际 Windows10/11 托盘权限、置顶窗口、最小化、系统通知禁用、电源/锁屏及极端磁盘故障需要最后实体机验收。微软系统可能限制托盘气泡通知；置顶本地窗口作为可见提醒冗余。
